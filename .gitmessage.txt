
# <type>(<scope>): <subject>
# 제목. 50자 내외의 명령형 문장.
# 예: feat(login): 소셜 로그인 기능 추가

# 본문. 변경 사항에 대한 구체적인 설명. '왜' 변경했는지 기술.

# 꼬리말. 이슈 트래커 번호 등.
# 예: Closes: #123

# --------------------------------------------------
# 커밋 타입 가이드라인
# --------------------------------------------------

# 기능 관련
# feat:      새로운 기능의 추가.
# fix:       코드의 버그를 수정.
# revert:    이전 커밋을 되돌림.

# 코드 품질
# refactor:  기능적 변경 없는 코드 구조의 개선.
# perf:      성능을 개선하는 코드 변경.
# style:     코드 의미에 영향 없는 스타일 수정 (포맷팅, 세미콜론 등).

# 기타
# docs:      문서(README 등)의 추가 또는 수정.
# test:      테스트 코드의 추가 또는 수정.

# 시스템 및 설정
# build:     빌드 시스템이나 외부 종속성에 영향을 주는 변경.
# ci:        CI/CD 관련 설정 파일의 수정.
# chore:     소스나 테스트 파일이 아닌 기타 파일의 수정 (설정, .gitignore 등).
